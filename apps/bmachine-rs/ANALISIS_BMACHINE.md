# ANALISIS BMachine C# — Peta Lengkap Logika & Fungsi

> **Tujuan dokumen ini:** peta cara kerja aplikasi BMachine (C#/Avalonia) supaya port Rust/Slint-nya benar secara **fungsi**, bukan cuma tampilan.
> **Metode:** read-only — hanya `muse.read` pada file teks di `~/workspace/mono-bmachine/apps/bmachine/`. Tidak ada build, run, git, atau perubahan file repo.
> **Tanggal analisis:** 26 Nov 2026. **Versi:** `BMachine.App.csproj` menulis **15.15.1** (dokumen `RANGKUMAN_PROJECT_BMACHINE.md` masih menulis 8.3.0 — sudah usang; badge README 6.5.0 juga usang).
> **Stack:** C# 12, .NET 8 (`net8.0`), Avalonia 11.3.22, MVVM CommunityToolkit.Mvvm 8.2.2, SQLite (`Microsoft.Data.Sqlite`), tema Semi.Avalonia + Fluent, ikon Tabler outline.
> **Catatan batas:** beberapa ekor file belum dibaca penuh (`BatchViewModel.cs` dari ~baris 3300, `SettingsViewModel.cs` dari ~baris 2849, `SpreadsheetViewModel.cs` dari ~baris 1165, `OutputExplorerViewModel.cs` dari ~baris 3240, ekor `replace.jsx`). Hal yang tidak ditemukan di kode dicatat eksplisit sebagai **tidak ditemukan**, bukan diasumsikan ada.

### Startup flow (`Program.cs`, `App.axaml.cs`, `Services/Bootstrapper.cs`)

## 2. Data & Penyimpanan

### Database — SQLite, BUKAN LiteDB (koreksi penting)

`src/BMachine.Core/Database/DatabaseService.cs` mengimplementasikan `IDatabase` + `IActivityService` di atas `Microsoft.Data.Sqlite`, `PRAGMA journal_mode=WAL`, timeout 15 detik. Lokasi file: `Path.Combine(platform.GetAppDataDirectory(), "BMachine.db")` — di Windows **`%APPDATA%\BMachine\BMachine.db`** (override env var `BMACHINE_APPDATA_ROOT` untuk run dev terisolasi; Linux `~/.config/BMachine`, macOS `~/Library/Application Support/BMachine`). File pendukung di folder yang sama: `.logs/debug.log`, `crash_report.txt`, `mantradata_settings.json`, `FolderLocker/config.enc`.

Hanya **2 tabel**, tanpa koleksi LiteDB:

1. **`KeyValueStore` (`Key TEXT PRIMARY KEY, Value TEXT, Type TEXT, UpdatedAt TEXT`)** — semua settings & cache disimpan sebagai JSON per key (`GetAsync<T>`/`SetAsync<T>`/`DeleteAsync`/`QueryAsync<T>`; `QueryAsync` memfilter berdasarkan `Type` = nama lengkap tipe .NET, dan secara eksplisit mengecualikan key `trello.apikey`/`trello.token`). Pola key-value generik, bukan tabel per entitas.
2. **`Activities` (`Id INTEGER PK AUTOINCREMENT, UserId, Type, Title, Description, CreatedAt`)** — log aktivitas via `LogAsync()`; dibaca `GetRecentAsync(count)` dan `GetCountAsync(type)`, dihapus `ClearAsync()`.

**Apa disimpan di mana:**
- **DB (`KeyValueStore`):** hampir semua settings aplikasi, konfigurasi board/list Trello, path Google/Sheet, state window, shortcut, cache Trello (board/list/kartu — dipertahankan antar sesi sebagai "offline fallback", di-refresh saat app dibuka, bukan dihapus saat startup: key `Cache.List.{listId}`, `Cache.GSheet.Points`, `ManualCards.*`, `CommentPresets`).
- **DB (`Activities`):** riwayat aktivitas.
- **File JSON terpisah:** `mantradata_settings.json` (settings MantraData — Photoshop path, AI provider/endpoint/key, dsb.), `Scripts/scripts.json` (metadata script, ikut ter-copy ke output).
- **OS Credential Vault:** hanya kredensial Trello (lihat §2.1).
- **File terenkripsi:** `FolderLocker/config.enc` (password + TOTP secret locker).
- **File (bukan DB):** script Python/JSX di `Scripts/`, file PSD/foto hasil kerja di folder user, file kredensial Google (path-nya saja disimpan di DB).

### 2.1 Kredensial / token — lokasi & mekanisme (tanpa nilai apa pun)

- **Trello (`Trello.ApiKey`, `Trello.Token`) — OS Credential Vault, BUKAN di DB.** `DatabaseService` mencegat kedua key ini di `GetAsync`/`SetAsync`/`DeleteAsync` (`IsTrelloSecret()`): baca/tulis dialihkan ke `ISecureCredentialStore` dari `Security/PlatformCredentialStore.cs`. Windows: **Windows Credential Manager** via P/Invoke `CredReadW`/`CredWriteW`/`CredDeleteW`, target `BMachine/Trello.ApiKey` dan `BMachine/Trello.Token` (atau `BMachine/{BMACHINE_CREDENTIAL_SCOPE}/{key}` bila env var diset), username `BMachine`, persist `LocalMachine`, batas blob 5120 byte. macOS: Keychain (service `com.zhensmarks.BMachine`); Linux: Secret Service via `secret-tool`. Migrasi otomatis: bila vault kosong tapi masih ada nilai lama di `KeyValueStore`, nilai lama dibaca, ditulis ke vault, lalu dihapus dari DB dengan `PRAGMA secure_delete=ON` + `wal_checkpoint(TRUNCATE)`. Saat startup kedua kredensial dimuat ke cache in-memory `TrelloRequestSecurity.SetCachedCredentials()` untuk unduhan media inline; `TrelloRequestSecurity` juga menegakkan kredensial hanya dikirim ke `https://api.trello.com` (OAuth header) dan men-strip parameter `key`/`token` dari URL media.
- **Google (Drive/Sheets) — file kredensial eksternal + referensi di DB.** Di DB hanya tersimpan `Google.CredsPath` (path ke file kredensial Google — service-account JSON / file OAuth, file-nya sendiri di luar repo & di luar DB), `Google.SheetId`, `Google.SheetName`, `Google.SheetColumn`, `Google.SheetRow`. Tidak ditemukan token Google yang disimpan langsung di DB/vault.
- **Pixelcut — TIDAK ditemukan token/API key di kode C#.** Tidak ada key `Pixelcut*` di `SettingsPreloadService`, tidak ada di `DatabaseService`, tidak ada file `.env` di repo. Kemungkinan token (bila ada) hidup di sisi script Python / konfigurasi di luar repo — jangan diasumsikan ada sebelum dicek ke script terkait.
- **Tidak ada enkripsi umum untuk isi `KeyValueStore`** — settings non-Trello di DB tersimpan sebagai JSON plaintext (hanya kredensial Trello yang dialihkan ke vault, dan locker config yang dienkripsi file-nya).
- **Enkripsi lain di `Security/`:** `AesGcmCryptor.cs` — AES-256-GCM + PBKDF2-SHA256 200.000 iterasi, format kompatibel Python DMA Locker: header `DMA2` + salt 16 byte + nonce 12 byte + ciphertext + tag 16 byte; plaintext dikompres (zlib/Deflate) sebelum enkripsi. `FolderLockerConfig.cs` — password locker + TOTP secret disimpan terenkripsi AES-GCM di `%APPDATA%\BMachine\FolderLocker\config.enc` (kunci diturunkan PBKDF2 100.000 iterasi dari `username + "BMachineLock"` dengan salt tetap `BMachineFLock!!` — kunci dapat diturunkan ulang dari nama user Windows). `TotpService.cs` — TOTP via `OtpNet` (secret Base32, 6 digit, periode 30 detik, `otpauth://` provisioning URI untuk QR).

### 3.1 Panel SOURCE — apa isinya sebenarnya

**Isi: isi filesystem lokal dari folder sekolah yang di-drop.** `BatchViewModel.AddFolders(paths)` → tiap path jadi satu `BatchFolderRoot`, lalu `RefreshSource()` membuat `BatchNodeItem(SourcePath, true)` yang langsung `IsExpanded = true`. `BatchNodeItem.LoadChildren()` (lazy saat expand) membaca disk langsung dengan `Directory.EnumerateDirectories` lalu `EnumerateFiles`, urut natural-sort (angka `2` sebelum `10`), mengecualikan `desktop.ini` dan `.lnk`, dan memfilter ekstensi hanya bila `BatchNodeItem.AllowedExtensions` diset. Jadi yang tampil = **semua subfolder + semua file** di dalam folder itu, rekursif saat di-expand — **bukan daftar master**.

> **Koreksi pemahaman lama:** daftar bernomor seperti `1. PAS FOTO`, `2. FOTO10RP_FREE SEKOLAH`, `3. SOUVENIR_FREE ID CARD`, `4. SOUVENIR_FREE KARTU PELAJAR` adalah **subfolder level-1 di dalam folder sekolah/PILIHAN yang di-drop**, bukan daftar master untuk dipilih. (Sesuai penjelasan abeng 26 Nov 15:17: SOURCE membaca ISI folder sekolah yang dipilih.)

**Cara memilih folder — 3 jalur, semuanya path lokal (tidak ada daftar folder dari server/database):**
1. **Drag-drop (utama):** `DashboardView.axaml.cs:OnBatchDrop()`/`OnBatchDragOver()` — drop dari Windows Explorer ke Drop Zone (`"DRAG FOLDERS HERE"`, tampil bila `ShowDropZone`, alias `!HasFolders`) atau ke TreeView; hanya direktori + `.lnk` yang diterima; `.lnk` di-resolve targetnya lewat `cscript` VBS (`ResolveShortcutTarget()` di `BatchViewModel` dan `OutputExplorerViewModel`). Penting: `AddFolders()` **mengganti seluruh koleksi** (dispose root lama, buat `ObservableCollection` baru) — bukan append.
2. **Dari Explorer:** `OutputExplorerViewModel.BatchActionCommand` (kirim folder terpilih) dan `BatchScriptCommand` (kirim folder + nama skrip) → `BatchAddFoldersMessage` → `BatchViewModel.Receive()` → `AddFolders()`; `CopyMasterBrowserHere()` → `MasterBrowserSyncFromExplorerMessage` → `AddFolderAndSelect()` (ini satu-satunya jalur append satu folder + langsung select).
3. **Tidak ada** dialog folder-picker untuk menambah folder sumber di BATCH sendiri (`BrowseMaster*` hanya untuk path template master).

**Penamaan & prediksi output:** `GetRelativePathFromMonth()` menelusuri max 5 level ke atas mencari folder pola `DD MONTH YYYY` (regex `^\d{2}\s+\w+\s+\d{4}$`, mis. `02 AGUSTUS 2025`) lalu path relatif dihitung dari parent folder bulan itu. Kasus khusus `PILIHAN`: output diarahkan ke parent-nya dan label source = label output = nama parent (supaya sejajar dengan kolom OUTPUT). `OutputBasePath` dibaca dari DB `Configs.Master.LocalOutput` (`LoadOutputBasePathAsync()`).

**Tampilan tree:** `SourceTreeItems` (`BuildTreeItems()`) — bila hanya 1 source, baris root disembunyikan dan isi folder langsung jadi baris teratas (nama sudah di header `HeaderSourceName`); bila >1, root `BatchFolderRoot` ditampilkan (`ShowRootRows`).

### 3.2 Panel OUTPUT — apa isinya, kapan terisi

**Isi: cerminan folder hasil di disk, bukan daftar rencana.** `BatchFolderRoot.OutputPath = Path.Combine(OutputBasePath, relativePath)`. `RefreshOutput()` membuat `BatchNodeItem(OutputPath)` **hanya bila `Directory.Exists(OutputPath)`**; bila belum ada `OutputRoot = null` → header menampilkan chip `(pending)` (`IsOutputPending`, bila 1 source dan `OutputRoot` null).

**Kapan terisi — 3 pemicu:** (a) **otomatis oleh `FileSystemWatcher`** di `SetupOutputWatcher()` (Created/Deleted/Renamed, `IncludeSubdirectories = true` → `RefreshOutput()`), jadi begitu skrip master / copy master membuat folder/file output, panel langsung muncul; (b) **`RefreshCommand`** (`BatchViewModel.Refresh()`: `RefreshSource()` + `RefreshOutput()` untuk semua root); (c) setelah `ExecuteMaster()` selesai per folder (`item.RefreshOutput()` dipanggil). Sebelum skrip apa pun jalan dan folder output belum ada, panel OUTPUT kosong dengan label `(pending)` — itu normal.

Panel OUTPUT adalah `OutputTreeItems` (struktur sama dengan SOURCE, `SelectionMode="Multiple"`), lengkap dengan context menu sendiri (New Subfolder / Replace (Auto) / Copy Output Path / Delete Output Folder — yang terakhir **menghapus folder output dari disk**).

### 3.3 Apa itu "master" — dua arti yang dipakai bergantian

**(a) Master template = file `.psd`/`.psb`** di folder-folder yang dikonfigurasi di Settings (DB `Configs.Master.*`: `Profesi`, `Sporty`, `Profesi8R`, `PasFoto`, `Manasik10RP`, `Manasik8R`, `Wisuda10RP`, `Wisuda8R`, `LastTemplatePath`, `AdditionalPaths`, `PhotoshopPaths`). Dibrowse lewat `LoadMasterNodes()` (root = AdditionalPaths + MasterTemplatePath; `ScanDirectory()` hanya file `.psd`/`.psb`, lazy-load, ada thumbnail JPG pendamping via `ThumbnailCacheService.ResolvePairJpg`) dan `LoadPhotoshopNodes()` (khusus gambar `.jpg/.png/.bmp/.tiff`).

**`Scripts/batch_wrapper.py`** — resolver + penerjemah argumen. Mencari target dengan urutan `Master/<target>`, `Action/<target>`, `<target>` — **catatan: kodenya mengambil kandidat pertama tanpa memeriksa keberadaan file** (`for p in possible_paths: target_path = p; break`), lalu membangun argv per skrip (`pasfoto.py`, `manasik.py`, `wisuda.py`, `profesi_flat.py`, `buat_master.py`, `buat_master_duplikat.py`/`buat_master_buka_edit.py`/`_buat_master_buka_edit.py`); target lain → error `Unknown target script` (exit 4). `OKE BASE` diambil dari `config.json` bila argumen kosong. Output skrip di-stream, baris ber-prefix `[SCAN]`/`[DEBUG]` di-suppress. Return code diteruskan ke pemanggil.

### 3.4 Tombol BUAT MASTER — menjalankan `buat_master_duplikat.py` (abeng benar)

**Koreksi penting soal label:** tombol di bawah panel OUTPUT (`DashboardView.axaml`, StackPanel kanan-bawah, teks **`BUAT MASTER`**, ikon `IconCopy`) terikat ke **`ExecuteBuatMasterDuplikatCommand`**, bukan ke `buat_master.py`. `BatchViewModel.ExecuteBuatMasterDuplikat()` memeriksa `IsProcessing`, memastikan `Scripts/Master/buat_master_duplikat.py` ada (memperhatikan `CustomScriptsPath`), lalu set `SelectedMasterScript` ke file itu dan memanggil `ExecuteMaster()` → `batch_wrapper.py --target buat_master_duplikat.py --pilihan <source> --output <OutputBasePath> --okebase <…>`.

Ada juga `ExecuteBuatMasterCommand` di VM (menjalankan `buat_master.py`) — **di `DashboardView.axaml` yang dibaca tidak terlihat terikat ke tombol berlabel**; satu-satunya jalan UI ke `buat_master.py` adalah ikon footer (Order 8) dan menu konteks Explorer (lihat §3.5).

**Alur `Scripts/Master/buat_master_duplikat.py` (fase 2 manual, tanpa Photoshop/watcher):** argumen `<pilihan_path> <output_base> [oke_base] [--manifest=...]`; `_resolve_output_base()` fallback ke DB `Configs.Master.OkeBase`/`LocalOutput` bila argumen kosong; manifest dicari lewat `manifest_path_for(pilihan, output_base)` = `<output_base>/_bm_copy_edit/manifest_<sha1(pilihan)[:12]>.json` — **bila manifest tidak ada, error dan exit 1** ("jalankan dulu tombol master"). Langkahnya: (1) hitung `final_output_folder` via `_get_relative_path_from_month()` (folder bulan `DD MONTH YYYY`, fallback nama parent); (2) salin semua `.txt` dari tiap subfolder PILIHAN ke output dengan struktur cermin (overwrite, idempotent, aman ditekan ulang); (3) bila ada `oke_base`, buat shortcut output lokal via `create_shortcuts_in_output_local()` (diimpor dari `pasfoto.py`); (4) scan master manual — `_add_manual_masters_to_manifest()`: PSD di `<grup>/#MASTER/*.psd` (struktur baru) atau di root event `*.psd` (legacy) yang belum terdaftar, dipetakan job-nya dari foto sumber yang label foldernya cocok (`_map_source_jobs()`, `_photo_base_name()` mengubah mis. `(15).JPG`→`15`) atau mengikuti penomoran grup yang sudah ada; (5) `run_duplicate_only()` di `_photoshop_utils.py`: salin tiap `edit_psd` ke semua `jobs`-nya lewat `_fastio.batch_copy` paralel 4 worker (fallback `shutil.copy2`), default `skip_existing` (file yang sudah ada dilewati, tombol aman ditekan ulang), log per file `- [OK] 2.psd` / `SKIP_EXISTING`, plus flag `--overwrite-manual` untuk memaksa timpa.

### 3.5 `buat_master.py` (otomatis/orkestrator) vs `buat_master_duplikat.py`

**`Scripts/Master/buat_master.py` — orkestrator "One-For-All", fase 1 copy-edit.** Membaca path master + `OkeBase`/`LocalOutput` langsung dari SQLite `%APPDATA%\BMachine\BMachine.db` (`find_db_path()`/`read_db_value()`, tabel `KeyValueStore`). `detect_folder_types(pilihan)`: memeriksa nama subfolder level-1 + semua `NOTE.txt` sampai kedalaman 4 — keyword `PAS FOTO`/`PFM`/`PFB`, `PROFESI`/`SPORTY` (atau `10RP`/`8R` + subfolder khas `ASTRONOT/BRIMOB/CHEF/DAMKAR/DOKTER/PILOT/TNI/…`), `MANASIK`/`MSK`, `WISUDA`/`WSD`, plus prefix kode dari `.txt` lewat `master_codes.py` (`MSK/BML/BMP/KML/KMP`→manasik, `WSD/KRA`→wisuda, `PFM/PFB`→pasfoto; prefix lain yang ada di registry → `tambahan`). Lalu menjalankan skrip anak berurutan via `subprocess` (`profesi_flat.py`, `pasfoto.py`, `manasik.py`, `wisuda.py`, `tambahan_flat.py`), masing-masing dengan flag `--mode=copy-edit --phase=1 --manifest=<path stabil>` — tiap anak **menyalin 1 template edit ke folder output + mencatat daftar tujuan (`1.psd`, `2.psd`, …) ke manifest** (`manifest_add()` di `_photoshop_utils.py`). Setelah itu (default, mode `copy-edit`): `open_edit_psds()` membuka semua template di Photoshop via COM (pywin32, fallback PowerShell COM) **tanpa timer** — user edit + SAVE sesuka hati — lalu berhenti dan mencetak instruksi "tekan tombol DUPLIKAT PSD". Flag `--auto` mengembalikan perilaku lama: `run_copy_edit_phase2()` membuka semua template, memantau `Photoshop.Documents` via watcher PowerShell sampai tiap tab ditutup (timeout 1800 dtk), lalu menggandakan per dokumen yang ditutup (skip existing). `--no-open` melewati auto-buka; `--mode=direct` = perilaku lama tanpa Photoshop. Di akhir mencetak `SUMMARY_JSON:{total, errors, detected}`.

**`buat_master_duplikat.py` — hanya fase 2, manual, tanpa deteksi dan tanpa Photoshop** (lihat §3.4): tidak mendeteksi jenis folder, tidak menjalankan skrip anak, hanya membaca manifest yang sudah dibuat fase 1, menyalin `.txt`, membuat shortcut, lalu menggandakan template yang sudah diedit.

**"Otomatis di Explorer" — klarifikasi:** `buat_master.py` **tidak** berjalan otomatis saat folder di-drop atau saat Explorer dibuka. Yang otomatis adalah *eksekusinya setelah dipilih*: `OutputExplorerView.axaml.cs:OnContextRequested()` menyuntikkan **satu-satunya** item batch ke context menu Explorer — `"BUAT MASTER"` (khusus mencari `OriginalName == "buat_master.py"` di `ScriptOptions`) — dengan `BatchScriptCommand` → `OutputExplorerViewModel.BatchScript()` mengirim `BatchAddFoldersMessage(paths, "buat_master.py")` + `NavigateToPageMessage("Batch")` → `BatchViewModel.Receive()` menambahkan folder, memilih skrip itu, pindah ke Console, dan **langsung `ExecuteMaster()`**. Ada juga `OutputExplorerViewModel.ExecuteFolderScript()` (menjalankan skrip langsung dari Explorer via wrapper tanpa lewat Batch) — di kode yang dibaca tampaknya tidak dipakai oleh menu tersebut.

**Ringkasan dua fase (alurnya):**
1. **Fase 1 — `buat_master.py`** (via ikon footer Order 8 / context menu Explorer): deteksi jenis → salin 1 template edit per jenis ke output + catat tujuan ke manifest → buka template di Photoshop → user edit + SAVE.
2. **Fase 2 — tombol BUAT MASTER (`buat_master_duplikat.py`)**: salin `.txt` → buat shortcut output lokal → scan master manual di `#MASTER` → gandakan tiap template edit ke semua tujuannya.

### 3.6 REPLACE dan "Replace (Auto)" — apa yang di-replace, multiple replace

**Yang di-replace: isi Smart Object/foto di dalam file master `.psd`/`.psb` (folder OUTPUT/master) dengan foto dari folder SOURCE/input.** `Scripts/Action/replace.jsx` ("Smart Object Replacer", ExtendScript Photoshop). Dijalankan dari BATCH tanpa dialog oleh `BatchViewModel.LaunchReplaceScriptAsync()`: validasi kedua folder ada, ambil path Photoshop dari DB `Configs.Master.PhotoshopPath`, tulis wrapper sementara `%TEMP%\bmachine_replace_auto_<guid>.jsx` berisi `$.global.BMachineBatchContext = {SourceFolders:[{SourcePath, OutputPath}], OutputBasePath, UseInput, UseOutput, MasterTemplatePath, BatchAutoReplace:true}` lalu `RunJsxInPhotoshop()`. Di `replace.jsx:main()`, bila `BatchAutoReplace`, dialog dilewati: tiap pasangan divalidasi, `runReplacementLogic(masterFolder, inputFolder, …)` dieksekusi **berurutan dalam satu pemanggilan Photoshop**, lalu satu laporan gabungan (`showCombinedReport()`); error ditulis ke `%TEMP%\bmachine_result.json`. PSD hasil replace **tetap terbuka** di Photoshop untuk diedit/disimpan user.

**Logika pencocokan (`runReplacementLogic()`):** scan rekursif template `.psd/.psb` di folder master dan file input (filter ekstensi dari `replacer_settings_v2.json`: mode `auto` = PNG/PSD diutamakan, JPG cadangan; atau paksa `jpg`/`png`/`psd`); cocokkan **berdasarkan nama file** (nama dasar sama, dengan strip suffix ` (1)`, dan hanya dalam subfolder yang sama/turunannya — kecuali template di root boleh fallback ke mana saja), bila gagal cocokkan **berdasarkan nomor awal nama file**; progress ditulis ke `%TEMP%\bmachine_progress.json`. Mode manual (dialog) punya panel Master + Input, auto-detect input dari server (`DEFAULT_BASE_INPUT = \\delapanmataair\Editor 5\2. REGULER\#PROJECT SEKOLAH\2026-2027`, `parseMasterPath()`/`autoDetectInputFolder()` mem-parsing bulan/sekolah/target dari path master dan mencari `PILIHAN/<target>`), tombol `+ Tambah ke Antrian` (queue internal `queueData`), `REPLACE` dan `REPLACE REVISI` (mode Persis/Fleksibel).

**Multiple REPLACE — dua lapis:**
1. **BATCH multi-select:** `ReplaceBatchFolderAsync(target, isOutputSide, manual:false)` — bila `SelectedSourceItems`/`SelectedOutputItems` berisi >1 item, tiap item di-resolve lewat `TryResolveReplaceFolders()` (cari `BatchFolderRoot` pemilik via prefix path terpanjang, hitung path relatif subfolder, pasangkan `Output = root.Output+rel` dengan `Source = root.Source+rel`; bila target adalah root, relatif = kosong) lalu semua pasangan dikirim sekaligus ke `LaunchReplaceScriptAsync(string[][] pairs)`. Target klik-kanan hanya fallback bila seleksi = 1. `DashboardView.axaml.cs` menjaga multi-seleksi tetap utuh saat klik-kanan (menyimpan lalu mengembalikan `SelectedItems` via Tunnel handler) dan mengimplementasikan Shift-click range-select manual; `UpdateSelectedSourceItems()`/`UpdateSelectedOutputItems()` menyinkronkan seleksi TreeView ke VM (`IsMultiSelectionActive = count > 1`).
2. **`ReplaceAllAutoCommand`** di VM: semua root `SourceFolders` menjadi pasangan sekaligus — ada di VM, tetapi **tidak terlihat terikat** di `DashboardView.axaml` yang dibaca.
3. Queue internal `replace.jsx` untuk mode dialog manual.

**Replace manual:** `ReplaceSourceManual`/`ReplaceOutputManual` → event `RequestManualReplaceFolderBrowse` → `DashboardView.axaml.cs:HandleRequestManualReplaceFolderBrowse()` membuka folder picker ("Select matching Source / Input folder" / "Select matching Output / Master folder") untuk memasangkan folder secara manual bila auto-pairing salah. Di `DashboardView.axaml` yang dibaca, menu konteks tree hanya menampilkan **"Replace (Auto)"** (`ReplaceSourceAutoCommand`/`ReplaceOutputAutoCommand`); command Manual ada di VM tetapi tidak terikat di menu tersebut.

### 3.8 Tambah/hapus folder; klik kiri vs kanan

- **Tambah folder sumber:** drag-drop (§3.1), dari Explorer (§3.1), atau **New Subfolder** di dalam folder yang sudah ada — tiga caranya: (i) context menu → "New Subfolder..." → input inline (`BatchNodeItem.ShowNewFolderInputCommand` → `CreateSubFolder()` → `Directory.CreateDirectory(Path.Combine(FullPath, nama))`, lalu expand/refresh); (ii) input inline di baris root (`BatchFolderRoot.ShowNewFolderInputCommand` / `CreateSubFolderCommand`, dan versi output `ShowOutputNewFolderInputCommand` / `CreateOutputSubFolderCommand`); (iii) overlay + Tambah Folder (§3.7). Tidak ada tombol "Tambah Folder" berupa folder-picker dialog.
- **Hapus:** ada dua makna berbeda — **hapus dari daftar** (`RemoveFolderCommand` per root, `ClearCommand` semua; hanya menghapus dari `SourceFolders`, file di disk aman) vs **hapus dari disk** (`DeleteCommand` di `BatchNodeItem`/`BatchFolderRoot`: `Directory.Delete(path, true)` / `File.Delete()`, lalu kirim `FolderDeletedMessage` → root yang cocok dihapus dari daftar atau `Refresh()`; `DeleteOutputCommand` menghapus folder output dari disk + dispose watcher). Hati-hati: menu "Delete Source Folder"/"Delete" adalah hapus permanen dari disk.
- **Klik kiri pada nama node:** **benar, copy path** — nama node adalah `Button` (`plainLink`) dengan `CopyPathCommand` (hanya untuk direktori; `BatchNodeItem.CopyPath()` menulis `FullPath` ke clipboard) dan `DashboardView.axaml.cs:OnNodePointerPressed()` pada klik kiri tunggal juga menyalin path **dan** men-set `SelectedBatchItem` + target Master Browser (`SelectBatchItemFromTree()`), kecuali bila Ctrl/Shift ditekan (supaya multi-seleksi tidak reset).
- **Klik kanan: bukan expand** — klik kanan membuka **context menu** (New Subfolder / Replace (Auto) / Copy Path / Delete). Expand/collapse dilakukan lewat chevron `ToggleButton` di `TreeViewItem` (template `FlatBatchTreeItem`, `IsExpanded` two-way) atau `ExpandCommand` (`ToggleExpand()` → `LoadChildren()` lazy).
- **Double-click file:** teks (`.txt/.json/.xml/.log/.md/.jsx/.js/.csv/.ini`) → `OpenTextCommand` → dibuka di Log Panel Console (`OpenTextFileMessage`, pindah ke `SelectedActivityMode = 0`); `.psd/.psb` → `SendFileToPhotoshop()`; gambar (`.jpg/.png/.jpeg/.bmp/.tiff`) → aplikasi default OS. Double-click folder tidak melakukan apa-apa (`HandleDoubleTap()` return bila direktori).

### 3.9 Proses batch lain — antrean, progress, log

- **Tidak ada antrean/queue di `BatchViewModel`.** `ExecuteMaster()` memproses **semua `SourceFolders` secara sekuensial** (`foreach`, `await RunPythonProcess()` per folder, lalu `RefreshOutput()`), dengan `IsProcessing = true` selama jalan; `ExecuteAction()` menjalankan satu Action script (`.jsx` → `RunJsxInPhotoshop()` dengan konteks JSON ditulis via `BmachineContextService.WriteContextAsync()`; `.pyw` → `RunPythonScript()` langsung). Tidak ada pemrosesan paralel antar folder.
- **Progress/log:** tidak ada progress bar/persentase di UI BATCH — hanya status `IsProcessing` + pesan `ProcessStatusMessage` (di `DashboardViewModel`: `ProcessStatusText` "Running {script}…", `IsLogPanelOpen` otomatis dibuka saat proses mulai) dan streaming log baris-per-baris dari Python ke `IProcessLogService` (ditampilkan di Log Panel; `DashboardViewModel.ParseLog()` membersihkan tag `[INFO]/[ERROR]/…` dan menerjemahkan beberapa pesan). `replace.jsx` menulis progress mentahnya ke `%TEMP%\bmachine_progress.json`, tetapi tidak ada kode BATCH yang dibaca membacanya kembali. **Stop:** `DashboardViewModel.StopProcessCommand` → `StopProcessMessage(true)` → `BatchViewModel.KillProcess()` (`_currentProcess.Kill(true)`, membunuh tree proses wrapper + Python).
- **Yang punya antrean sungguhan:** (a) `replace.jsx` mode dialog — queue internal `queueData` + tombol `+ Tambah ke Antrian` (§3.6); (b) Explorer — `FileOperationManager` + `TaskMonitorWindow` (copy/move/delete background dengan progress, undo, retry) untuk operasi file Explorer, bukan untuk batch master; (c) `buat_master.py` fase `--auto` — watcher COM Photoshop (timeout 1800 dtk) yang menggandakan per dokumen saat ditutup (§3.5).

### 4.1 Dari mana angka EDITING / REVISION / LATE / POINTS berasal

**EDITING / REVISION / LATE = Trello API (live), bukan hitungan lokal dari due date.** `DashboardViewModel.SyncTrelloStats()` memanggil `RefreshCommand` dari tiap list-VM, lalu menghitung `Cards.Count(c => !c.IsSeparator)` — jadi angka = jumlah kartu di **satu list Trello yang dipilih user di Settings**, dikurangi baris separator dummy. Persentase bar = `count / 10` (konstanta `MAX_CARDS = 10.0`, di-cap 1.0).

| Widget | Sumber | Kunci setting (di SQLite) |
|---|---|---|
| EDITING | `EditingCardListViewModel.Refresh()` → `FetchCards(Trello.EditingListId)` | `Trello.EditingListId` (+ `Trello.EditingBoardId`) |
| REVISION | `RevisionCardListViewModel.Refresh()` → `FetchCards(Trello.RevisionListId)` | `Trello.RevisionListId` |
| LATE | `LateCardListViewModel.Refresh()` → `FetchCards(Trello.LateListId)` | `Trello.LateListId` |
| POINTS | **Google Sheets, satu sel** — `DashboardViewModel.SyncTrelloStats()` | `Google.CredsPath`, `Google.SheetId`, `Google.SheetName`, `Google.SheetColumn`, `Google.SheetRow` |

- **Trello — `BaseTrelloListViewModel.FetchCards(listId, apiKey, token)`:** `GET https://api.trello.com/1/lists/{listId}/cards?fields=name,desc,due,labels,idMembers,badges,cover,pos,shortUrl&checklists=all&attachments=true&attachment_fields=url,name`. Yang diparse ke `TrelloCard`: `Id`, `Name`, `Description`, `DueDate` (+ flag `IsOverdue = due < DateTime.Now`), label (nama+warna), checklist (nama + hitung `ChecklistTotal`/`ChecklistCompleted`), `AttachmentCount`, cover (warna + URL via `cover.idAttachment` → array `attachments`), `Pos`, `ShortUrl`. **Nama board/list tidak di-hardcode** — user memilih board lalu list di Settings (`SettingsViewModel.RefreshTrelloData` → `GET /members/me/boards`; `FetchListsAsync` → `GET /boards/{id}/lists`); yang disimpan hanya ID-nya.
- **Khusus EDITING — `EditingCardListViewModel.Refresh()`:** gabungan 3 sumber: (a) kartu list Trello, (b) kartu manual dari `ManualCards.Editing` (daftar ID di DB, diambil satu-per-satu lewat `FetchSingleCard`, ditandai `IsManual = true`), (c) kartu ACC dari `ManualCards.Acc` (ditandai `IsAcc = true`, diletakkan di bawah separator dummy `"Menunggu ACC Marketing"`, `IsSeparator = true`). Kartu ACC yang masih ada di list utama dikeluarkan dari daftar utama agar tidak dobel.
- **POINTS — bukan Trello dan bukan leaderboard:** satu sel spreadsheet, range `{SheetName}!{Kolom}{Baris}` (mis. `Sheet1!B2`), dibaca via Google Sheets API dengan service-account (`GoogleCredential` dari file `Google.CredsPath`, scope `SpreadsheetsReadonly`). Nilai sel ditampilkan apa adanya sebagai string (`StatPoints`); persentase = nilai / 1500 (`MAX_POINTS`). Kalau file kredensial tidak ada → `StatPoints = "ErrFile"`. Kalau konfigurasi kosong → widget diam di nilai lama. Hasil sukses di-cache ke `Cache.GSheet.Points`. **Jangan disamakan dengan leaderboard:** `PointLeaderboardViewModel.LoadData()` membaca *range* terpisah (`Leaderboard.Range` harian, `Leaderboard.MonthlyRange` bulanan) dari sheet yang sama, mengurutkan nama+poin menurun, memberi `Rank`, dan menghitung total poin user yang login (`ActiveTotalPoints`). Widget ke-4 di `DashboardView.axaml` bahkan berlabel hardcode `"SPREADSHEET"` (suffix `POIN`), bukan `"POINTS"`.
- **Arti tiap angka:** EDITING = beban kerja yang sedang dikerjakan; REVISION = kartu yang sedang revisi/QC; LATE = kartu di list susulan (lihat §5.3 — ini list tersendiri, **bukan** hasil filter overdue); POINTS = satu angka poin dari sel Sheets (konteksnya leaderboard/poin editor).
- **Sinkronisasi angka ke UI (3 lapis):** (a) `CollectionChanged` pada `TrelloVM.{Editing,Revision,Late}VM.Cards` di `DashboardViewModel.InitializeChildViewModels`; (b) `SyncTrelloStats()` yang dipanggil tiap 1 detik oleh `_timer` tapi hanya benar-benar refresh kalau interval terlampaui (lihat §4.3); (c) safety timer 2 detik yang memaksa samakan `Stat*` dengan jumlah kartu bila event kelewat. Notifikasi Windows (`TriggerWindowsNotification`, via PowerShell `NotifyIcon`) + log `Activities` hanya muncul bila jumlah kartu **bertambah** — dan hanya bila file `Plugins\Notifikasi.dll` ada.

Panel-panel lain (Comment, Checklist, Move, Attachment) bersifat eksklusif — `CloseAllSidePanels()` dulu — dan di mode compact jadi layar penuh (`ShouldShowPanelScreen`, `CompactBack` menutup LIFO: Comment → Checklist → Move → Attachment → Detail).

### 4.3 Nav HOME / BATCH / LOCKER — kapan tampil/sembunyi

Nav di `DashboardView.axaml` adalah pill terpusat: HOME selalu tampil; BATCH `IsVisible="{Binding IsBatchVisible}"`; LOCKER `IsVisible="{Binding IsFolderLockerVisible}"`. `SelectedTabIndex`: 0=Home, 1=Batch, 2=Locker, 5=Points, 6=Explorer (dipakai `Receive(NavigateToPageMessage)` dan `OpenLeaderboard`).

- **`IsBatchVisible`** (`DashboardViewModel`, default `true`): dimuat di `LoadVisualSettings()` dari `Settings.Dash.Batch` (default `"True"` bila kosong). Di Settings, `SettingsViewModel.IsBatchVisible` → `SaveAndNotifyDashboard("Settings.Dash.Batch", value)` → kirim `SettingsChangedMessage` + `DashboardVisibilityChangedMessage`.
- **`IsFolderLockerVisible`** (`DashboardViewModel`, default `true`): dimuat di `LoadVisibilitySettings()` dari `Settings.Dash.Lock` (default `"True"`), dan diperbarui live lewat `Receive(SettingsChangedMessage)` **hanya untuk key `Settings.Dash.Lock`**. Di Settings, `SettingsViewModel.IsFolderLockVisible` → `SaveAndNotifyDashboard("Settings.Dash.Lock", value)`.
- Catatan duplikasi yang membingungkan: ada **dua** properti locker di `DashboardViewModel`: `IsLockerVisible` (juga dimuat dari `Settings.Dash.Lock` di `LoadVisualSettings()`) dan `IsFolderLockerVisible`. Yang di-binding nav XAML adalah `IsFolderLockerVisible`; `IsLockerVisible` tidak terikat ke nav yang dibaca. Begitu pula `IsPointVisible` dan `IsOutputExplorerVisible` dimuat dari `Settings.Dash.Point` / `Settings.Dash.Explorer` tapi tab Points/Explorer tidak ada di pill nav (diakses lewat command lain). Jadi sumber kebenaran tunggal tampil/sembunyi BATCH dan LOCKER adalah toggle di Settings → kunci `Settings.Dash.Batch` / `Settings.Dash.Lock` di SQLite; default keduanya tampil.

### 4.4 Sinkronisasi, interval refresh, dan penanganan error/offline

**Tidak ada real-time (websocket/polling Trello).** Semua sinkronisasi berupa polling HTTP + refresh manual:

| Mekanisme | Interval / pemicu |
|---|---|
| `DashboardViewModel` — timer `_timer` + `SyncTrelloStats()` | Tick tiap **1 detik**, tapi tiap list hanya di-`Refresh()` bila intervalnya terlampaui: `EditingRefreshSeconds` / `RevisionRefreshSeconds` / `LateRefreshSeconds` / `PointsRefreshSeconds` (field default 30 dtk di Dashboard; `LoadVisualSettings` memakai 60 dtk bila DB kosong; `SettingsViewModel` default 60 dtk; bisa diubah di Settings → kirim `RefreshDashboardMessage`) |
| `Editing/Revision/LateCardListViewModel.StartAutoRefresh()` | `DispatcherTimer` **60 detik**; tiap tick panggil `CheckForUpdates(listId)` dulu (GET `.../lists/{id}/cards?fields=id,badges` — bandingkan set ID + progres checklist `checkItems/checkItemsChecked`) dan hanya `Refresh()` bila ada perubahan. Sekali jalan per tab (`UnifiedTrelloViewModel.EnsureActiveTabAutoRefreshStarted`, flag `_editing/_revision/_lateAutoRefreshStarted`) — tab yang tidak aktif tidak di-refresh saat startup |
| `DashboardViewModel.CheckConnectivity()` | Tiap **10 detik** `GET https://www.google.com/generate_204` (timeout 2 dtk) → `IsOnline` / `IsSpreadsheetOnline` |
| Fokus aplikasi | `AppFocusChangedMessage`: timer dashboard 5 dtk (fokus) / 60 dtk (background); timer tiap list-VM di-stop saat background, start lagi saat fokus |
| Checklist panel | Poll **10 detik** selama panel terbuka (`PollOpenChecklistsAsync` → `SyncChecklists`) |
| Points (Sheets) | Mengikuti `PointsRefreshSeconds`; di dalam `Task.Run` fire-and-forget, maks. 2 percobaan + backoff 500 ms → 1000 ms |

**Penanganan error/offline:**
- `FetchCards`: sukses → simpan JSON mentah ke `Cache.List.{listId}` di SQLite + `IsOnline = true`; gagal → `IsOnline = false`, baca cache; cache kosong → daftar kosong. `StatusMessage` menampilkan "Config missing." (key/token/list kosong), "Memuat data..."/"Refreshing...", "Dimuat N card", atau "Error: {pesan}". `IsRefreshing` selalu di-reset di `finally`. Kartu manual yang gagal di-fetch dipertahankan dari `_cachedManualCards`.
- `IsOnline = false` menampilkan teks status "Offline" (`ConnectionStatusText`) + dot merah di `UnifiedTrelloView`, banner "SYSTEM OFFLINE [READ ONLY]" di panel detail Editing, dan tombol Move di-disable (`IsEnabled="{Binding IsOnline}"`).
- Points: kredensial hilang → `StatPoints = "ErrFile"`; gagal jaringan → nilai lama dipertahankan (kode `StatPoints = "Err"` sengaja dikomentari/dinonaktifkan); sukses → `Cache.GSheet.Points`.
- Umum: hampir semua `catch` menelan exception menjadi `StatusMessage`/log debug (`Debug.WriteLine` berisi hanya nama tipe exception, tanpa detail) — jadi dari UI, kegagalan terlihat sebagai status text, bukan dialog error.

## 5. Trello — Integrasi

**Tidak ada SDK/library Trello dan tidak ada kelas `TrelloService`.** Semua panggilan berupa `HttpClient` mentah ke `https://api.trello.com/1/...` dengan auth OAuth header (`Authorization: OAuth oauth_consumer_key="...", oauth_token="..."`) yang dipasang `TrelloRequestSecurity.ApiOnlyAuthenticationHandler`. Handler itu menolak mengirim kredensial ke host selain `api.trello.com` (HTTPS, port default, tanpa userinfo) dan membuang parameter query `key`/`token` dari URL (`TryNormalizeMediaUri`) — jadi kredensial tidak pernah menempel di query string. Timeout default 30 detik (15 detik untuk `FetchCards`, 10 detik untuk `CheckForUpdates`, 15 detik untuk komentar).

### 5.1 Kredensial

- `TrelloApiKey` (input manual) + `TrelloToken`. Token lewat `GetTrelloToken()`: `https://trello.com/1/authorize?expiration=30days&name=BMachine%20Task%20Panel&scope=read,write&response_type=token&key={apiKey}` — **token berlaku 30 hari**, jadi koneksi akan mati tiap bulan bila tidak diperbarui.
- Disimpan lewat `_database.GetAsync/SetAsync<string>("Trello.ApiKey" / "Trello.Token")` (dialihkan ke OS vault, lihat §2.1); setiap ketikan dijadwalkan autosave 500 ms (`ScheduleTrelloCredentialSave` → `SaveTrelloCredentialsAfterTypingAsync`) dan sekaligus `TrelloRequestSecurity.SetCachedCredentials(...)` (cache statis untuk unduhan media). `SaveProfile()` juga menyimpan keduanya + `Trello.IsConnected`.
- `ToggleTrelloConnection()` / `SmartTrelloAction()`: Connect butuh key+token (kalau token kosong → buka halaman authorize); Disconnect mengosongkan semua `Trello.*BoardId/ListId` + `Trello.IsConnected = False` dan membersihkan daftar board/list di Settings. `IsTrelloConnected` hanya flag boolean di DB — tidak ada validasi token berkala; kegagalan ketahuan saat fetch gagal.
- **Board/list yang dipakai:** tidak ada nama board/list hardcode. Yang ada: `Trello.EditingBoardId/EditingListId`, `Trello.RevisionBoardId/RevisionListId`, `Trello.LateBoardId/LateListId`, plus `Trello.QcBoardId` (tujuan auto-move, §5.3) dan `Trello.AccBoardId/AccListId` (tujuan ACC Marketing). Semua dipilih user di Settings dari hasil `GET /members/me/boards` + `GET /boards/{id}/lists`. Nama board/list aktual tidak bisa disebut dari kode — hanya ID yang disimpan.

### 5.3 Bagaimana status kartu berubah (Editing → Revision → Late)?

**Tidak ada transisi status otomatis di kode.** Tidak ada state machine, tidak ada aturan "due date lewat → pindah ke Late", tidak ada tombol "Selesai/QC" yang memindahkan kartu. Yang ada:

- **Pindah manual** adalah satu-satunya cara berpindah list/board: panel Move / batch move (`PUT /cards/{id}?idList=&idBoard=`, §5.2). Jadi Editing → Revision → Late terjadi karena **user memindahkan kartu di Trello (atau lewat app ini)** ke list yang dikonfigurasi sebagai Revision/Late.
- **LATE bukan hasil komputasi overdue.** `LateCardListViewModel` hanya membaca `Trello.LateListId` seperti list biasa. `IsOverdue` (`DueDate < DateTime.Now`, dihitung di `FetchCards`/`FetchSingleCard`) hanya flag di model — tidak ditemukan pemakaian `IsOverdue` untuk memfilter, memindah, atau menandai visual kartu di template yang dibaca. Kartu yang due-nya lewat tapi masih di list Editing tetap dihitung di EDITING, bukan di LATE.
- **Sinyal "selesai dikerjakan" yang ada di kode adalah checklist, bukan pindah list:** `TrelloCard.IsChecklistDone` = ada checklist bernama `#EDITING {UserName}`; label kartu berubah TODO → DONE. Checklist itu dibuat lewat `DuplicateChecklist` (nama default `#EDITING {UserName.ToUpper()}`).
- **Satu-satunya otomatisasi pindah kartu: `AutoMoveCard`** — dan itu pun hanya jalan saat user membuka panel Move (`ShowMovePanel` memanggilnya dulu; bila berhasil, panel tidak dibuka). Logikanya: nama kartu di-split `_`, segmen ke-3 (`parts[2]`) dicocokkan `Contains` (case-insensitive) dengan nama list di board QC (`Trello.QcBoardId`, `GET /boards/{qcBoardId}/lists`); kalau cocok → `DataMoveCard` ke list itu ("Moved to QC: {nama list}"). Bila nama < 3 segmen atau tidak cocok → return false, panel Move normal dibuka.
- **Alur ACC (persetujuan Marketing), khusus Editing:** `BatchAcc()` (tombol ACC di action bar, hanya kartu reguler terseleksi, bukan manual/ACC) → `PUT /cards/{id}?idList={AccListId}&idBoard={AccBoardId}` + simpan ID ke `ManualCards.Acc`; kartu lalu tampil di seksi "Menunggu ACC Marketing". Ini satu-satunya "status" tambahan selain list Trello — dan sifatnya lokal (ID disimpan di DB) + posisi fisik kartu di board ACC.

**Rujukan:** `Services/UpdateService.cs`, `Services/LocalUpdateService.cs`, `Models/UpdateInfo.cs`, `ViewModels/MainWindowViewModel.cs`, `ViewModels/SettingsViewModel.cs` (bagian update), `Views/Dialogs/UpdateDialogWindow.axaml`.

**Koreksi penting: jalur aktif BUKAN GitHub Releases.** Ada **DUA jalur update**. `UpdateService.cs` (GitHub) masih ada — `GET https://api.github.com/repos/zhensmarks/BMachine.v2/releases/latest`, membandingkan `tag_name` (tanpa awalan v) dengan versi assembly — tetapi **jalur yang aktif dipakai aplikasi adalah update lokal/LAN (`LocalUpdateService`)**, bukan GitHub.

Tombol terapkan → `LocalUpdateService.ApplyAsync()`: verifikasi SHA256 exe payload terhadap manifest (bila hash beda, update dibatalkan); tulis helper PowerShell ke `%TEMP%\bmachine-update-<guid>.ps1` yang menyalin payload ke folder instalasi.

**Hot update vs restart.** Bila hanya ISI file skrip yang berubah (tanpa file skrip baru/hilang dan tanpa perubahan exe/Assets — dinilai `EvaluateRestart()` dari daftar file + hash di manifest), update diterapkan **TANPA restart** (hot update; versi dicatat di `%AppData%\BMachine\applied_hot_version.txt` agar banner tidak muncul lagi sampai restart; daftar script di-refresh via `RefreshScriptsMessage` + `ScriptOrderChangedMessage`). Bila perlu restart (exe/Assets berubah, atau ada file skrip baru/dihapus), helper menunggu proses ini keluar (maks 180 detik), menyalin, lalu membuka aplikasi lagi; aplikasi menutup sendiri setelah jeda 1,2 detik. **Tampilan dialog** (`UpdateDialogWindow.axaml`): lebar 380 px, tinggi mengikuti isi, tanpa chrome, Topmost, header "PEMBARUAN TERSEDIA" + chip versi + chip ukuran, baris versi saat ini, catatan rilis dalam scroll (maks 200 px), panel pemilih komponen (hanya bila manifest punya components; teks penjelas: komponen yang tidak dicentang tidak disentuh; hanya file yang berubah yang disalin kecuali MASTER yang disalin utuh; perubahan isi skrip saja = aplikasi tidak ditutup), tombol "Perbarui sekarang" (`ApplyUpdateCommand`) dan "Nanti" (`DismissUpdateCommand`), progress bar indeterminate + teks status saat menerapkan.

### 6.11 FolderLocker (`FolderLockerView`)

**Rujukan:** `ViewModels/FolderLockerViewModel.cs`, `BMachine.Core/Security/FolderLockerService.cs`, `FolderLockerConfig.cs`, `TotpService.cs`, `AesGcmCryptor.cs`.

**Fungsinya: mengunci folder dengan enkripsi file (AES-256-GCM), bukan sekadar menyembunyikan/mengunci folder di OS.** `FolderLockerService.LockFolderAsync()` membuat salinan folder dengan akhiran `_ORI` yang berisi file terenkripsi (struktur subfolder dipertahankan, tiap file jadi `<nama>.dma`); file asli di folder sumber **tetap tidak disentuh** menurut kode yang dibaca. File `.dma` yang sudah ada dilewati saat mengunci. `UnlockFolderAsync()` membaca file `*.dma` (rekursif), mendekripsi dengan password yang sama, menulis kembali file asli (menghapus akhiran `.dma`) dan menghapus file `.dma`-nya.

**Kunci dibuka dengan kode OTP TOTP (bukan password saja).** Setup di `FolderLockerViewModel.EnterSetup()` / `GenerateSetup()` — user memasukkan password + konfirmasi password (harus cocok dan tidak kosong), lalu `TotpService.GenerateSecret()` membuat secret baru, QR code dibuat dari provisioning URI (`TotpService.GetProvisioningUri(secret, "FolderLocker", "BMachine")`, digambar via QRCoder) untuk dipindai aplikasi authenticator, dan konfigurasi (password + secret) disimpan via `FolderLockerConfig.Save()`. Bila konfigurasi sudah ada, setup menampilkan ulang QR dari secret yang tersimpan. `ResetSetup()` menghapus konfigurasi (`FolderLockerConfig.Reset()` + `ReloadConfig()`).

**Alur pakai.** Pilih folder (`BrowseFolder()` / `SetFolder()`) → preview maks 10 file teratas (ikon gembok untuk `.dma`, ikon file untuk normal) + hitungan file normal vs terkunci (`CountFiles()`) + status `CanLock` (ada file normal DAN sudah terkonfigurasi) / `CanUnlock` (ada file `.dma` DAN sudah terkonfigurasi) → Lock (progress persen + nama file, bisa Cancel via `CancellationTokenSource`) → status "Selesai! Semua file terkunci."; Unlock: `StartUnlock()` menampilkan input OTP → `ConfirmUnlock()` → `UnlockFolderWithOtp()` → verifikasi OTP dulu (`TotpService.Verify()`; bila salah/kedaluwarsa, lempar `UnauthorizedAccessException` "Kode OTP salah atau expired.") baru dekripsi. `SettingsViewModel` membaca `FolderLockerConfig.Load().IsConfigured` sebagai `IsLockerConfigured`. Catatan: bagian setup FolderLocker di Settings ditandai "(Temporarily Disabled)" di komentar kode. Dialog Locker dibuka dari Dashboard (`OnLockClick()`) sebagai window 540×480 yang mengingat posisi/ukuran terakhir di konfigurasi locker.

**Detail kripto.** `AesGcmCryptor.cs` — AES-256-GCM, format kompatibel Python DMA Locker: header `DMA2` + SALT 16 + NONCE 12 + CIPHERTEXT + TAG 16; PBKDF2 200.000 iterasi; data dikompresi dulu sebelum dienkripsi. `FolderLockerConfig.cs` — konfigurasi disimpan terenkripsi di disk di `%APPDATA%\BMachine\FolderLocker\config.enc` (AES-GCM, kunci diturunkan via PBKDF2 100.000 iterasi SHA256 dari username + "BMachineLock" dengan salt tetap "BMachineFLock!!"); juga menyimpan geometri window (default 540×460). `TotpService.cs` — OtpNet, secret acak 20 byte Base32, URI `otpauth://totp/BMachine:FolderLocker`, 6 digit, periode 30 detik, jendela verifikasi ±1 langkah.

### 6.13 Logika domain dari `STUDI_MASTER_CREATOR.md` (aplikasi DMA `master_creator` — rujukan alur kerja BATCH)

Dokumen studi ini (hasil reverse-engineering aplikasi DMA `master_creator.exe`, PySide6) menjelaskan pola kerja yang dicerminkan BATCH BMachine:

- **Tiga konsep inti:** Direktori kerja (daftar folder sekolah + mana yang aktif: `selected_dir_list`, `selected_dir`); Master (sumber) = folder master per jenis produk (di server/LAN: `default_path_pasfoto`, `default_path_manasik`, `default_path_wisuda`, `default_path_profesi`, `default_path_sporty`, `default_path_free_sekolah`, `default_path_sovenir_plakat/_mendali/_hanging/_box_pensil`, `default_path_bersama_*`); Output (#OKE) = folder hasil per sekolah, diingat per folder (`dir_output_context`: path → `last_output_folder`).
- **Drop = daftar kerja persisten:** folder yang di-drop masuk `selected_dir_list` (normalisasi + dedupe), bertahan antar sesi. Kalau nama folder terakhir adalah `PILIHAN`, yang ditampilkan nama folder induknya.
- **Status folder: PROSES (kuning) / ACC (hijau)**, saling eksklusif; folder berstatus PROSES ditolak diproses ("Folder ini statusnya PROSES. Ubah dulu ke ACC lewat DM.").
- **Scanner Folder Reguler:** root dari config `folder_reguler_path`, scan 3 level `BULAN > MARKETING > SEKOLAH` (thread terpisah untuk UNC), filter bulan + search, klik kanan Add Folder / Open Folder. **Add Folder hanya menerima folder yang punya subfolder `PILIHAN`.**
- **Resolusi `PILIHAN` yang toleran** (`_resolve_pilihan_dir`): basename `PILIHAN` → pakai itu; `<path>/PILIHAN` ada → pakai itu; cari anak folder bernama `PILIHAN` (case-insensitive); gagal → `''`.
- **Deteksi jenis kerja dari NAMA FOLDER (tahan typo):** SPORTY/SPOTRY, NON REG, BERSAMA/ANGKATAN/POSTER/KALENDER, WISUDA/WISHUDA/WSD/MANASIK/MSK, PROFESI/OB, FREE_SEKOLAH (FREE + SEKOLAH/SEKOALAH/…), PAS_FOTO (PAS + FOTO/PHOTO/POTO), PLAKAT/PLAKET/PLKAT, MENDALI/MEDALI, BOX_PENSIL, HANGING/HANGEN/HANGIN.
- **Deteksi dari NOTE:** baca semua berkas `NOTE`/`NOTES`/`BACA`/`BACAA` (`.txt/.text/.md/.rtf` atau tanpa ekstensi) untuk deteksi kode PLAKAT/HANGING/MEDALI dan kode manasik/wisuda (token `[A-Za-z0-9]+`, pola `^(\d+)([A-Z])$`, `^[A-Z]$`, `^\d+(R|RP)$`).
- **Pipeline per produk** (`proses_pilihan` = dispatcher): `COPY MASTER …` (salin PSD master ke folder `MASTER` di folder sekolah) → `BUAT MASTER …` (buka PSD di Photoshop, replace foto, simpan; tunggu Save; auto-continue) → follow-up queue → cek selesai. Varian: `(AUTO)`, `(SINGLE)`, `(PERKELAS)`, `(Skip Copy)`.
- **Mode BATCH & AUTO:** `buat_folder_otomatis` — REGULER (satu sekolah) / **REGULER BATCH** (ulang proses yang sama untuk **semua folder sekolah di daftar kerja**, memakai konfigurasi default dari run REGULER pertama) / SUSULAN (`#OKE SUSULAN <keterangan>`). Mode SERVER: output otomatis ke `folder_marketing_path`. Hasil: struktur `#OKE …` + shortcut `#OKE Pindah Kesini.lnk`, `DOC.lnk` + penanda `DOC LOCK (BAHAN EDITOR)` dan berkas `.dma`.
- **Protokol Photoshop** (`replace_auto_normal.jsx`, headless): baca `replace_params.json` (`masterPath`, `inputPath`, `maxPerPart`, `skipProgress`, `mode`, `excludeDirNames` default `["BAHAN"]`, `resultPath`); scan master & input rekursif, natural sort, cocokkan input ke master lewat **angka depan** yang sama, `maxPerPart` (30 normal, **70** untuk SINGLE/HANGING) → proses per part; replace XL & S (atau XL saja), progress bar + cancel; tulis `replace_result.json`: `{cancelled, successNumbers[], successCount, failCount}`.
- **Yang belum ada di BMachine** (menurut studi, dan inilah yang bikin `master_creator` terasa cepat): daftar kerja sekolah persisten + combo pindah cepat; status PROSES/ACC per folder; ingatan output per sekolah; scanner Folder Reguler; resolusi `PILIHAN` toleran; deteksi jenis dari nama folder; deteksi master dari NOTE.txt; REGULER BATCH; quantity checker JPG/PSD/PNG + pembedaan group (`001 (1).jpg`) vs single + export `EDITOR Quantity Checker.txt`.

### Implikasi konkret untuk port Slint (per fase)

**Fase 2 BATCH — perlu dirombak mengikuti §3 (bukan sekadar poles tampilan):**
- SOURCE harus menjadi **tree filesystem asli**: baca direktori yang di-drop (subfolder + file), expand lazy, natural sort, sembunyikan root bila 1 source, header = nama folder. Daftar bernomor di contoh abeng adalah subfolder level-1 — tampilkan apa adanya dari disk.
- OUTPUT harus menjadi **cerminan folder hasil di disk** (hanya bila ada) + chip `(pending)` bila belum ada; refresh otomatis saat file muncul (di Rust: polling direktori / notify watcher).
- Tombol BUAT MASTER = **alur duplikat fase 2** (manifest → salin .txt → shortcut → gandakan template). Orkestrator `buat_master.py` dipicu dari ikon footer / context menu Explorer — bukan dari tombol BUAT MASTER.
- Footer ikon skrip = **launcher skrip** (dari `scripts.json`, 32×32, tooltip `Name (file)`); pertahankan, tapi pahami sebagai sekunder.
- REPLACE = **aksi Photoshop via `replace.jsx`**: seleksi multi-item di tree (Shift-click range-select) → pairing source/output via prefix path terpanjang → satu pemanggilan Photoshop dengan konteks JSON. Sediakan juga Replace manual (folder picker) sebagai fallback bila auto-pairing salah.
- Interaksi tree: klik kiri nama = copy path (+ select); klik kanan = context menu (New Subfolder / Replace (Auto) / Copy Path / Delete); expand via chevron; double-click teks → tampilkan di log console, `.psd` → Photoshop, gambar → aplikasi default.
- Tambah folder: **drag-drop (mengganti daftar)** + dari Explorer; tidak ada folder-picker untuk source. Hapus: bedakan "hapus dari daftar" vs "hapus dari disk".
- Proses: sekuensial per folder, status `IsProcessing` + log streaming, tombol Stop (kill process tree). Tanpa antrean, tanpa progress bar.

**Fase 3 Trello — perlu disesuaikan:**
- Klik StatWidget → **satu view bertab** (`UnifiedTrelloView`: EDITING/REVISI/SUSULAN), bukan 3 layar daftar terpisah. Panah kecil di widget = jendela terpisah (`CardListWindow`).
- Angka = jumlah kartu di list yang dikonfigurasi (minus separator); LATE = list tersendiri; POINTS = satu sel Sheets (label "SPREADSHEET").
- Daftar kartu: baris berisi checkbox seleksi + judul + badge ACC / DONE-TODO + garis cover; due date/deskripsi/label hanya di panel detail.
- Detail kartu: chip cover, tanggal event (regex dari deskripsi), chip ID (klik → cari di Spreadsheet), chip attachment, chip Due, label berwarna, tombol Copy Link / Buka di Browser / Comment / Checklist / Move / Unlink (manual saja). Panel samping eksklusif (LIFO saat compact).
- Komentar = timeline komentar + aktivitas; kirim komentar dengan upload gambar dulu (inline markdown); `@mention` dari anggota board; preset maks 5.

- Sinkronisasi: polling per list (interval 30–60 dtk, bisa diubah di Settings) + `CheckForUpdates` diff tiap 60 dtk; cache SQLite offline; banner "SYSTEM OFFLINE [READ ONLY]" + Move di-disable saat offline.

**Fase 4 (RadialMenu/Toolbox/Explorer/Spreadsheet/Leaderboard):**
- RadialMenu: kanvas 200, pusat (100,100), radius 72, tombol 36, maks 7 item + navigasi di 180°; pilih by sudut pointer (deadzone pusat < 40 px, luar > 154 px); submenu cincin luar radius 128 (dwell 300 ms); grup di `__groups__.json`; editor slot di Settings.

- Log panel: tab EXPLORER/LOG/MASTER/PHOTOSHOP/DOC; watcher `%TEMP%\bmachine_progress.json` + `bmachine_result.json`; Terminal toggle; lebar 180–600 px.

**Fase 5 (Settings/dialog/splash/log panel):**

Perhatian bug wrapper: mengambil kandidat path pertama tanpa cek keberadaan file.

- Plugin: muat DLL dari folder `plugins/` (manifest `plugin.json`); data plugin terisolasi prefix `plugin:{id}:`. (Di Rust: plugin kemungkinan diganti modul bawaan / skrip — perlu keputusan terpisah.)
- **Yang TIDAK dibangun dari asumsi:** modul Pixelcut (tidak ada di kode C#), upload Drive (tidak ada di kode), update GitHub (jalur aktif = LAN).
